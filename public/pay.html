💳 Mercury402 Payment Flow

Use x402 payment-signature, not legacy bearer tokens

! Legacy token flow is deprecated

Production no longer accepts manually generated x402_... bearer tokens.

That flow was replayable and got ripped out. Use an x402-compatible client or payment processor that returns a signed payment-signature payload.

1 Make the unpaid request

Endpoint: /v1/treasury/yield-curve/daily-snapshot
Quoted price: $0.00 USDC
Network: Base (eip155:8453)
curl -i https://api.mercury402.com/v1/treasury/yield-curve/daily-snapshot

The server returns 402 Payment Required plus a Payment-Required header with the x402 descriptor.

2 Pay with an x402-compatible client

Use the descriptor from Payment-Required to create a real x402 payment. Your wallet or payment service should submit a signed EIP-3009 authorization and return a base64-encoded payload for the payment-signature header.

USDC contract:

0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913

Mercury recipient (payTo):

0xF8d59270cBC746a7593D25b6569812eF1681C6D2

3 Retry with payment-signature

curl https://api.mercury402.com/v1/treasury/yield-curve/daily-snapshot \
  -H "payment-signature: <base64_x402_payment_payload>"
One payment, one redemption.

Mercury now enforces one-time redemption. Reusing a previously accepted payment artifact gets rejected.
